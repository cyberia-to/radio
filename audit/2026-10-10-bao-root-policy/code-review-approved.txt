PLAN v3's approval is not inherited; I re-derived the semantics from the supplied bytes. The implementation is correct against pinned Hemera authority, ROOT is applied exactly once and only on a terminal complete-file node, all traced producers/verifiers/stores/tickets agree, and the scope boundaries (public signature, counters, odd promotion, allocation, geometry, `Hash::EMPTY`, MemStore width) are respected. ## What I verified in the diff

**Single shared reducer.** `cyber-bao/src/io/mod.rs::hash_group<B: HashBackend>` is the only reduction left. The four private clones are gone (`outboard.rs::hash_block`, `decode.rs::hash_block_for_verify`, `slice.rs::hash_block_for_verify`, `sync.rs::hash_subtree`) and their call sites now use `super::hash_group`. The sync argument-order hazard was handled correctly: `hash_subtree(&backend, 0, &tmp, true)` → `hash_group(&backend, &tmp, 0, true)` and `hash_subtree(backend, start_chunk, &buf, is_root)` → `hash_group(backend, &buf, start_chunk, is_root)`. Public `io::hash_block` keeps `block_bytes` plus `let _ = block_bytes;` and delegates, so `fsm.rs`, `mixed.rs`, `sync::encode_ranges_validated` and `iroh-blobs/src/util.rs::outboard_with_progress::hash_subtree` inherit the fix with no edit — consistent with semver 202/202 pass on both crates.

**ROOT applied exactly once, only at the file root.** `is_root && level.len() == 2` is evaluated on the *current* level before `next` is built; `while level.len() > 1` means `len == 2` is reached exactly once and is always the final iteration (`ceil(2/2) == 1`). No earlier parent and no promoted odd node can receive ROOT. Reaching `hash_group(.., is_root = true)` with more than one chunk requires `BaoChunk::Leaf{is_root: true}`, which `tree.rs` emits only via the `blocks == 1` early return in `pre_order_chunks`/`post_order_chunks`: for `blocks >= 2` the root node `blocks.next_power_of_two() - 1` always has a populated right child (`blocks > npot/2`), so `right_exists` is true and `is_root` is never inherited down to a leaf. Equivalently `hash_group(is_root=true)` ⟺ the group *is* the whole file. Empty/single-chunk and multi-group roots are therefore unchanged, and the delta is confined to `4096 < N <= 4096·2^g` (log4: 4097..65536).

**Behaviour-preserving otherwise.** Chunk counters remain absolute (`counter = start_chunk + i`), `is_single_chunk = data.len() <= CHUNK_SIZE && is_root` matches the old per-site logic including the old `sync` `len <= CHUNK_LEN` shortcut, odd promotion still `level[i].clone()` (generic `B::Hash: Clone`, no Poseidon hardwiring), and the Vec/SmallVec allocation strategy is untouched. The only differing flag is the terminal parent's.

**Generic-backend evidence is decisive.** `root_policy_tests::Recording` uses a deliberately non-`Copy` `type Hash = Vec<u8>` with length-prefixed, injective encodings, and `unreachable!()` on `hash_size`/`zero_hash`/`hash_from_bytes` (so the reducer is proven not to serialize). `empty_and_single_leaf_preserve_absolute_counter_and_root` pins counter 37 for len 0/1/4096 × root false/true; `finalization_and_odd_promotion_are_independent_of_group_position` pins full expected trees for 2/3/5 leaves at counter 37 with `parents == [false; n-1]` and last `== root`. This is exactly the guard that a non-root group cannot be ROOT-finalized.

**Producer/verifier/store/ticket agreement.** `tests/root_policy.rs` carries the required evidence: the independent 8192-byte literal `2abf65dd…0190` (and old CV `11890a7e…7389`) reaching `hash_block`, `outboard`, `PreOrderMemOutboard`, `PostOrderMemOutboard`, `encode`, `extract_slice_ranges`; acceptance through `decode`, `decode_slice`, `encode_ranges_validated` (`== wire[8..]`) and `valid_ranges` with **exact** cardinality 1 and `ChunkNum(0)..ChunkNum(2)`; old-CV rejection with the exact pinned variants per path and empty encoder output; mixed = `Size(8192), Leaf{0,D}, Done, Ok(())` vs `Size(8192), Error(LeafHashMismatch(ChunkNum(0)))` with no trailing `Done` (slice patterns, so extra items would fail); FSM leaf-then-`Done` vs `LeafHashMismatch`. `grouping_preserves_fixed_tree_at_boundaries` compares `outboard(..).root` with `fixed_chunk_root` across 14 lengths × logs 0/1/2/4 — a whole-tree equivalence check that also covers the required 16385/log4, 24576/log2 and 28672/log2 cases. `non_root_partial_and_odd_groups_verify_with_absolute_counters` supplies the unchanged right-only multi-group proofs (24576/log2 4+2, 28672/log2 4+3, 65537/log4 16+1 — the last pinning that a single-chunk non-root group is not root-finalized). `published_empty_and_hello_tree_vectors_are_unchanged` uses the published tree vectors and correctly avoids CDC `tree.4k_zeros`. Native side: `hash/root_policy.rs` pins the published anchors, `Hash::new == fixed_chunk_root == literal`, and that both canonical- and old-rooted `BlobTicket`s round-trip byte-identically without normalisation; `export_pairs.rs` exercises `ReadonlyMemStore` (→`CompleteStorage::create`), `MemStore::add_bytes` (→`import_bytes`/`finish_import`, `list().hashes()`), and two separate `FsStore`s at `is_inlined_all(8192)` true/false, each asserting the key equals `Hash::new`, `fixed_chunk_root` and the literal, plus exact `LE64(8192)||D` export and `get_bytes`. ## Behavioural identity break

**Accept as scoped.** It is required by `specs/tree.md` §74–97 and restores the stated invariant that a file root is never an internal CV of a larger file sharing the prefix at the same counters. Conditions, all already recorded: source semver green certifies nothing about wire/key compatibility; no alias or dual acceptance; old keys/tickets/collection references must be reconstructed from complete bodies (partial records cannot); HashSeq bodies of `32·(1+children)` put 128..2047-child collections inside the affected interval; rollback does not migrate canonically-written records. No release/tag/promotion action is taken here.
